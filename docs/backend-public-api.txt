================================================================================
TENANCY (PER REQUEST)
================================================================================
Public routes resolve organization PER HTTP REQUEST. They do NOT use
PUBLIC_ORGANIZATION_SLUG.

Identifiers
  Header: x-website-api-key  -> Organization.settings.websiteApiKey
  Query:  organizationId     -> Organization._id  (GET and POST query string)

Rules
  1. Key + organizationId, same org     -> allow
  2. Key + organizationId, different    -> 403 Forbidden (never pick one)
  3. Key only                           -> allow (GET and inquiry)
  4. organizationId only                -> allow GET only
  5. organizationId only on inquiry     -> 401 (key required)
  6. Neither                            -> GET 400, inquiry 401

Every Mongo query for public properties/builders/stats/inquiries is scoped
with organizationId = resolvedOrganizationId.

Cross-tenant property id  -> 404 (not 403, do not leak other tenants)
Inquiry propertyId must belong to the resolved org or the request is rejected.

Frontend env
  VITE_API_BASE_URL
  VITE_WEBSITE_API_KEY     sent on every /public/* request
  VITE_ORGANIZATION_ID     sent as query organizationId on every /public/* request

================================================================================
1) LIST PROPERTIES
================================================================================
GET /public/properties

Used for: home, listings, search, filters, compare, similar properties.
Frontend: properties.service.ts getAll — loops page=1..50, limit=100, until
meta.hasNext is false, then merges local demo inventory.

cURL
  curl -sS "${BASE}/public/properties?page=1&limit=100&sortBy=price&sortOrder=desc"

Query params the frontend actually sends
  page, limit
  sortBy          price | area | newest | createdAt
  sortOrder       asc | desc
  search
  category        omitted when "buy"; else rent | commercial | new_projects | pg | plot | luxury
  city, locality, sector, pincode, landmark
  minPrice, maxPrice, minArea, maxArea
  bedrooms
  status          spaces -> underscores
  type            comma list of API enums (apartment,villa,...)
  bhk             comma list (studio,1_bhk,2_bhk,3_bhk,4_bhk,5_plus_bhk)
  amenities       comma list (gym,swimming_pool,...)
  propertyAge, furnishing, facing, possessionStatus

Backend also accepts (frontend query object has them, but they are NOT sent):
  builder, featured, reraOnly, readyToMove, underConstruction, possessionYear
  Those only affect local/demo merge on the website.

data[] = Property objects (see PROPERTY OBJECT below).

2) GET ONE PROPERTY
================================================================================
GET /public/properties/:id

Frontend: getById, timeout 5s, fallback to local demo if fail/not found.

data = one Property. 404 -> Property not found.

================================================================================
5) CREATE INQUIRY (LEAD)
================================================================================
POST /public/inquiries

Used for: home, contact, property-detail lead forms.
Frontend: inquiries.service.ts submit.
Then FormSubmit email (best-effort). Then WhatsApp redirect (not an API).

cURL
  curl -sS -X POST "${BASE}/public/inquiries" \
    -H "Content-Type: application/json" \
    -H "x-website-api-key: WEBSITE_API_KEY" \
    -d '{
      "firstName": "Asha",
      "lastName": "Khan",
      "phone": "9810000000",
      "email": "asha@example.com",
      "city": "Gurugram",
      "message": "Site visit",
      "budget": 8500000,
      "propertyId": "PROPERTY_ID"
    }'

Required: firstName, lastName, phone (min 10 chars)
Optional: email, city, message, budget (number INR), propertyId

Success (HTTP 201): data { "id": "<leadId>", "message": "..." }
Frontend requires success=true AND data.id.

Backend maps to CRM lead:
  source type WEBSITE (or name "Website")
  createdBy first active admin of the resolved public org
  status NEW
  If propertyId set, property must belong to that same public org.

================================================================================
PROPERTY OBJECT (what the UI needs)
================================================================================
id, title, description
listingCategory     buy | rent | commercial | new_projects | pg | plot | luxury
type, status
price, pricePerSqFt, area, carpetArea, builtUpArea, superArea
bedrooms, bathrooms, configuration
address, city, state, pincode, locality, sector, landmark
latitude, longitude
builderName, projectName, propertyAge, furnishing, facing
possessionStatus, possessionDate, roiPotential
postedBy            backend currently hardcodes "Durga Property"
isVerified, hasRera, reraId, featured, luxury
hasVideoTour, videoTourUrl, virtualTourUrl, brochureUrl
amenities[], highlights[]
nearbySchools[], nearbyHospitals[], nearbyMetroStations[]
images[]            { id, url, isPrimary, caption }
                    relative url -> {API host without /api/v1}{url}

Backend serializePublicProperty currently returns images: [] and a subset of
fields. Extra fields are tolerated. Missing numbers default to 0; locality
falls back to city; listingCategory defaults to buy.
